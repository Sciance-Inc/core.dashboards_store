# Seeds

## Mandatory seeds
::alert{type=warning}
These seeds must be populated for the ETL to work.
::

::alert{type=success}
If you have spun up your store using the `cookiecutter` template, the `cssXX.dashboards_store/seeds/marts/human_resources/` folder already contains pre-populated seeds to help you get started. You just have to update the `csv` files with your own business rules.
::

The following table shows the required seed definitions and the path where the `csv` files should be placed.

| Seed YAML definition path | Where to save it | Name of the seeds to implement | Scope |
| --- | --- | --- | --- |
| `core.dashboards_store/seeds/marts/human_resources/schema.yml` | `cssXX.dashboards_store/seeds/marts/human_resources/*.csv` |  etat_empl, stat_eng | Human resources mart |
| `core.dashboards_store/seeds/marts/human_resources/schema.yml` | `cssXX.dashboards_store/seeds/marts/human_resources/*.csv` | heure_quotidienne, type_absence, code_paiement | Human resources absence models |

Seeds that are only used by a dashboard are documented on the corresponding dashboard page.

::alert{type=info}
**Getting started with the seeds.** Please check the `analyses/bootstrap` folder of your newly created repo. You will find some pre-built queries that will help you pre-populate the seeds.
::

# Adapters

## Mandatory adapters
::alert{type=warning}
These `adapters` must be populated to run the human resources models that consume student populations.
::

The following table shows the required adapter definitions and the path where the `sql` files should be placed.

| Adapter YAML definition path | Where to save it | Name of the adapter to implement | Scope |
| --- | --- | --- | --- |
| `core.dashboards_store/models/marts/human_resources/staging/adapters.yml` | `cssXX.dashboards_store/models/marts/human_resources/staging/*.sql` | stg_ele_primaire_reg_raw, stg_ele_secondaire_reg_raw | Human resources models tagged `efficacite` |

These `raw` populations are similar to the regular educational-services populations, but they must also include inactive students. Avoid blindly copying the active-student filter used by the `educ_serv` populations.
