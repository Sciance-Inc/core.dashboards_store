# Déploiement
:badge[tag:res_epreuves]{type="success"}
:badge[new in v0.19.0]

## Base de données
La base de données `gpi` doit être liée au projet. Consultez la section [lier une base de données](/fr/using/configuration/databases) pour plus d'informations.

## Spécification du projet *dbt*
> Mettez à jour votre fichier `cssXX.dashboards_store/dbt_project.yml` avec l'extrait suivant.

1. Activer les modèles et *dashboards* du *repo* *core*

```yaml
# cssXX.dashboards_store/dbt_project.yml
models:
  core_dashboards_store: # Active les modeles du repo core
    marts:
      educ_serv:
        +enabled: True
    dashboards:
      educ_serv:
        res_epreuves:
          +enabled: True
    interfaces:
      gpi:
        +enabled: True
      jade:
        +enabled: True
```

1. Définir la variable `cod_css`
   ::alert{type=warning}
   La variable `cod_css` est requise pour filtrer les résultats provenant des tables Jade et exclure les élèves d'autres CSS. Cette variable DOIT être définie pour que le *dashboard* fonctionne correctement.
   ::

```yaml
# cssXX.dashboards_store/dbt_project.yml
vars:
  # Variables du dashboard res_epreuves:
  dashboards:
    res_epreuves:
      cod_css: ###% -- Les trois premiers caracteres de votre CSS. Format regex SQL, p. ex. '001%' pour CSS001
```

# Configuration
## Ajouter des épreuves locales

::alert{type=warning}
La configuration est optionnelle. Si vous ne fournissez pas de configuration, le *dashboard* utilisera la configuration par défaut.
::

- Pour ajouter une liste d'épreuves locales à suivre dans le *dashboard*:

  1. Ajoutez un fichier `.csv` dans le dossier `cssXX.dashboards_store/seeds/dashboards/res_epreuves`. Le fichier doit s'appeler `rstep_epreuves_personnalisees`. Il doit être rempli avec les colonnes décrites dans `core.dashboards_store/seeds/dashboards/res_epreuves/schema.yml`, qui décrit la *seed* `rstep_epreuves_personnalisees`.

  2. Déclenchez un rafraîchissement de vos *seeds*.

```bash
dbt seed --full-refresh
```

## Ajouter les données ministérielles

::alert{type=warning}
Cette configuration est optionnelle, mais fortement recommandée. Si vous ne fournissez pas les données Charlemagne, la section des épreuves uniques du *dashboard* n'affichera aucune donnée.
::

::alert{type=info}
La procédure suivante décrit comment ajouter les données ministérielles au *dashboard*. Elle est la même pour chaque session à suivre. Elle doit être effectuée manuellement pour chaque session, car les données ne peuvent pas être récupérées automatiquement depuis la base. La procédure est un peu lourde et nécessite le fichier Excel `fichier_traitement.xlsm` pour consolider les données des différentes sessions dans un seul fichier `.csv`.

Ce fichier se trouve dans le dossier `core.dashboards_store/analyses/dashboards/res_epreuves`.
::

- Pour ajouter les données régionales et provinciales des épreuves uniques au *dashboard*:

  1. Exécutez les rapports Charlemagne `CHS040509R - Statistiques provisoires des résultats d'épreuves uniques` pour toutes les sessions et années à suivre dans le *dashboard*.
  2. Enregistrez-les ensuite dans un seul dossier ne contenant que ces fichiers `XML`.
  3. Utilisez le fichier `fichier_traitement.xlsm`, situé dans le dossier `/analyses/dashboards/res_epreuves`, pour consolider les fichiers `XML` des différentes sessions dans un seul fichier `.csv`.
  4. Enregistrez le fichier consolidé dans `cssXX.dashboards_store/seeds/dashboards/res_epreuves` sous le nom `fichier_consolide_epreuves_ministerielles`.
  5. Déclenchez un rafraîchissement de vos *seeds*.
  6. Répétez ces étapes pour chaque session.
