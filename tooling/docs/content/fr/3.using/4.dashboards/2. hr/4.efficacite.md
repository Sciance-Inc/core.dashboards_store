::alert{type=info}
Tableau de bord permettant d’évaluer l’efficacité des ressources allouées en fonction des divers besoins des milieux et de la réussite éducative des élèves.
::

# Déploiement

:badge[tag:efficacite]{type="success"}

La base de données `paie` doit être liée au projet. Veuillez vous référer à la section [lier une base de données](/fr/using/configuration/databases) pour plus d’informations sur la façon de lier une base de données.

La base de données `gpi` doit être liée au projet. Veuillez vous référer à la section [lier une base de données](/fr/using/configuration/databases) pour plus d’informations sur la façon de lier une base de données.

La base de données `jade` doit être liée au projet. Elle fournit les résultats ministériels du secondaire utilisés pour le calcul du taux de réussite.

## *Marts*

Les *marts* suivants doivent être activés pour que le tableau de bord fonctionne. Consultez la section [activer un *mart*](/fr/using/configuration/enabling) pour plus d'informations.

- `human_resources`
- `educ_serv`

## Spécification du projet *dbt*

> Mettez à jour votre fichier `cssXX.dashboards_store/dbt_project.yml` avec l’extrait suivant.

```yaml
# cssXX.dashboards_store/dbt_project.yml
models:
  core_dashboards_store:
    marts:
      human_resources:
        +enabled: true
      educ_serv:
        +enabled: true
    dashboards:
      human_resources:
        efficacite:
          +enabled: true
      educ_serv:
        res_epreuves:
          +enabled: true
    interfaces:
      paie:
        +enabled: true
      gpi:
        +enabled: true
      jade:
        +enabled: true
```

Le tableau `res_epreuves` est une dépendance technique d’Efficacité : il produit les résultats ministériels du secondaire. Il n’est pas nécessaire de publier son fichier Power BI pour utiliser Efficacité.

# Checklist de déploiement

1. Lier les bases `paie`, `gpi` et `jade`, puis activer les *marts*, tableaux et interfaces de l'extrait ci-dessus.
2. Renseigner `eff_coefficients_premier_axes` et valider `eff_categories_emploi_personnalises` avec les ressources humaines.
3. Exécuter `analyses/dashboards/efficacite/bootstrap_eff_mapping_fgj_paie.sql`. Copier son résultat dans `eff_mapping_fgj_paie` : chaque ligne exacte utilise `lieu_jumele = ecole_gpi`.
4. Exécuter `analyses/dashboards/efficacite/diagnose_eff_mapping_fgj_paie_non_matches.sql`. Résoudre les lignes retournées avant de les ajouter au mapping; une ligne commentée rendrait la *seed* CSV invalide.
5. Créer une ligne `eff_reporting_configuration` pour chaque `lieu_jumele` retenu. Mettre `is_school_comparable` à `1` pour les écoles comparables; laisser nom et catégorie vides lorsque les métadonnées GPI doivent être utilisées.
6. Charger les *seeds*, construire les modèles Efficacité et `res_epreuves`, puis vérifier les tables `eff_conf_mapper` et `eff_conf_lieu_travail_sans_lieu_jumele` avant de brancher `efficacite.pbit`.

# Configuration

::alert{type=warning}
La configuration est facultative. Si vous ne fournissez aucune configuration, le tableau de bord utilisera la configuration par défaut.
::

## Configurer la *seed* `eff_categories_emploi`

::alert{type=info}
Consultez la section [*seeds*](/fr/using/configuration/adapts-seeds) pour plus d'informations sur l'utilisation et l'alimentation des *seeds*.
::

> Par défaut, la *seed* `core.dashboards_store/seeds/dashboards/human_resources/efficacite/eff_categories_emploi.csv` est utilisée si aucune *seed* personnalisée n'a été créée dans le répertoire `cssXX.dashboards_store`. Nous vous recommandons fortement de créer cette *seed* et de la configurer avec un employé du service des ressources humaines.

Pour créer la *seed* personnalisée, allez dans le répertoire `cssXX.dashboards_store/seeds/dashboards/human_resources/efficacite`, puis créez le fichier `eff_categories_emploi_personnalises.csv`. Vous devez vous fier à la définition décrite dans le schéma de la *seed*, situé dans `core.dashboards_store/seeds/dashboards/human_resources/efficacite/schema.yml`.

::alert{type=warning}
La configuration est obligatoire. Si vous ne fournissez aucune configuration, le tableau de bord ne va pas s'exécuter.
::

> Vous devez créer les trois *seeds* suivantes dans le répertoire `cssXX.dashboards_store/seeds/dashboards/human_resources/efficacite`:

-> `eff_coefficients_premier_axes`
-> `eff_mapping_fgj_paie`
-> `eff_reporting_configuration`

Comme indiqué ci-dessus, la définition des *seeds* est décrite dans le schéma situé dans `core.dashboards_store/seeds/dashboards/human_resources/efficacite/schema.yml`.

> Pour alimenter la *seed* `eff_coefficients_premier_axes`, vous devez exécuter le *script* Python situé dans `core.dashboards_store/analyses/dashboards/efficacite/Dashboard_efficacite_extract_coeff.py`. Assurez-vous ensuite d'inscrire les données dans les bonnes colonnes de la *seed*.

> Pour alimenter la *seed* `eff_mapping_fgj_paie`, vous devez extraire tous les `lieu_trav` de la table `i_pai_tab_lieu_trav`. Il faut ensuite faire une liaison avec `gpm_t_eco` pour extraire les écoles GPI (colonne `ecole_gpi`). Certaines valeurs peuvent être nulles. La colonne `lieu_jumele` est le numéro affiché comme école parent dans le tableau de bord. Par exemple, l'école 042 peut être une école satellite de 005.

Le `lieu_trav` est 042, l'`ecole_gpi` est 042 et le `lieu_jumele` est 005.

> Pour alimenter la *seed* `eff_reporting_configuration`, vous devez référencer le `lieu_jumele` de la *seed* `eff_mapping_fgj_paie`.
Si vous décidez qu'une école n'est pas comparable, vous pouvez l'exclure avec 0, sinon 1.
Si la colonne `lieu_jumele` n'est pas identique à la colonne `lieu_trav` dans la *seed* `eff_mapping_fgj_paie`, nous recommandons fortement d'écrire le nom et la catégorie de l'école du `lieu_jumele`. Selon l'exemple décrit ci-dessus pour `eff_mapping_fgj_paie`:

005,1,(005) - Saint-Paul,École primaire
