title: Activer une ressource
---

# Pourquoi faut-il activer quelque chose?

Par défaut, la Bibliothèque de tableaux de bord (le *Dashboards Store*) ne matérialise rien. Vous devez activer les modèles que vous voulez matérialiser. Cela évite de matérialiser des données inutiles: si vous ne vous intéressez qu'à un seul tableau de bord, vous n'avez pas besoin de matérialiser tout le `core_dashboards_store`.

# Comment activer une ressource?

> Une ressource peut être un ensemble de tables requises par un tableau de bord, un *mart* complet ou un seul fichier `.sql`.

::alert{type="info"}
La configuration `+enabled: True|False` est le mécanisme de *dbt* pour activer ou désactiver des ressources. Consultez la [documentation *dbt*](https://docs.getdbt.com/reference/resource-configs/enabled) pour en savoir plus. Ce mécanisme fonctionne aussi pour les **tests** et les ***seeds***.
::

L'activation d'un modèle se fait dans `cssXX.dashboards_store/dbt_project.yml`. Pour activer un modèle, ouvrez simplement `dbt_project.yml`, trouvez le nom de la ressource à activer et remplacez `+enabled: false` par `+enabled: true`.

## Exemple

### Activer un *mart*

J'ai ajouté mes *seeds* au *mart* de ressources humaines et je veux maintenant l'activer.

1. J'ouvre d'abord `cssXX.dashboards_store/dbt_project.yml` et je cherche la ressource `human_resources`. Je trouve ceci:

```yaml
models:
  core_dashboards_store:
    marts:
      human_resources:
        +enabled: False
```

2. Je remplace ensuite `+enabled: False` par `+enabled: True`:

```yaml
models:
  core_dashboards_store:
    marts:
      human_resources:
        +enabled: True
```

3. Et voilà.

### Activer un tableau de bord

Supposons que je veuille activer le tableau de bord `chronic_absenteeism`.

1. J'ouvre d'abord `cssXX.dashboards_store/dbt_project.yml` et je cherche la ressource `chronic_absenteeism`. Je trouve ceci:

```yaml
models:
  core_dashboards_store:
    dashboards:
      chronic_absenteeism:
        +enabled: False
```

2. Je remplace ensuite `+enabled: False` par `+enabled: True`:

```yaml
models:
  core_dashboards_store:
    dashboards:
      chronic_absenteeism:
        +enabled: True
```

### Activer une interface

::alert{type="info"}
Pour activer une interface, la base de données doit être liée. Consultez la section [lier une base de données](/fr/using/configuration/databases) pour plus d'informations.
::

Supposons que je doive activer l'interface `paie` pour matérialiser le *mart* RH.

1. J'ouvre d'abord `cssXX.dashboards_store/dbt_project.yml` et je cherche la ressource `paie`. Je trouve ceci:

```yaml
models:
  core_dashboards_store:
    interfaces:
      paie:
        +enabled: False
vars:
  database_paie: "replaceMeWithYourDatabase"
```

2. Je remplace ensuite la valeur de la variable `database_paie` par le nom de ma base de données. Consultez la section [lier une base de données](/fr/using/configuration/databases) pour plus d'informations.

```yaml
vars:
  database_paie: "dataServer.paie" # Nom de la base dans l entrepot. Il sera interpole dans la couche Interface.
```

3. Je remplace ensuite `+enabled: False` par `+enabled: True`:

```yaml
models:
  core_dashboards_store:
    interfaces:
      paie:
        +enabled: True
vars:
  database_paie: "dataServer.paie"
```

## Dépendances des ressources

Une erreur fréquente consiste à activer un modèle sans activer ses dépendances:

- Pour les ***marts***, cela signifie activer un *mart* sans activer les `interfaces` dont il dépend.
- Pour un ***tableau de bord***, cela signifie activer un tableau de bord sans activer les *marts* sur lesquels il est construit.

::alert{type="warning"}
Les pages de tableau de bord et de *mart* indiquent généralement leurs dépendances. Lorsque vous activez une ressource, assurez-vous d'activer aussi ses dépendances en amont.
::
