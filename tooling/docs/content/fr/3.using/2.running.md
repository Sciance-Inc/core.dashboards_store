# Introduction
*dbt* contient un orchestrateur intégré qui permet d'exécuter l'*ETL*. Seuls les modèles activés avec la syntaxe `+enabled: true` seront exécutés. Comme tous les modèles sont désactivés par défaut, seuls les modèles ou tableaux de bord que vous activez manuellement seront exécutés.

## Comment exécuter la Bibliothèque
::alert{type=warning}
Toutes les commandes *dbt* doivent être lancées depuis le projet `cssXX.dashboards_store`.
**AVANT** d'appeler une commande *dbt* depuis `cssXX.dashboards_store`, assurez-vous d'avoir activé l'environnement Poetry en exécutant `eval $(poetry env activate) && poetry install` depuis `core.dashboards_store`.
::

::alert{type=info}
Pour obtenir la liste complète des options disponibles, exécutez `dbt --help` ou consultez la [documentation officielle de *dbt*](https://docs.getdbt.com/reference/commands/run).
::

La commande de base pour exécuter et tester la Bibliothèque de tableaux de bord (le *Dashboards Store*) est la suivante:

```bash
dbt build
```

Cette commande est une alternative plus rapide à l'exécution manuelle des commandes suivantes:

```bash
dbt compile
dbt seed
dbt run
dbt test
```

### J'ai des besoins particuliers

#### Je dois recharger les définitions des *seeds*

Ajoutez l'option `--full-refresh`.

```bash
dbt build --full-refresh  # build peut être remplacé par run.
```

#### Je veux matérialiser les transformations dans un environnement autre que celui par défaut

Si vous voulez cibler un environnement autre que la *target* par défaut définie dans `~/.dbt/profiles.yml`, utilisez l'option `--target`. Vous en aurez besoin pour matérialiser la Bibliothèque en production.

```bash
dbt build --target prod  # build peut être remplacé par toute autre commande dbt, comme seed ou test.
```

#### Je veux exécuter seulement un fichier SQL précis

Si vous voulez exécuter seulement un fichier SQL précis, utilisez l'option `--select`.

```bash
dbt build --select <sql_file_name>  # Le nom du modèle est le nom du fichier SANS l'extension `.sql`.
```

#### Je veux exécuter seulement un tableau de bord précis

Si vous voulez exécuter seulement les modèles d'un *mart* ou d'un tableau de bord précis, utilisez l'option `--select +tag:<model>`.

```bash
dbt build --select tag:<nom_du_dashboard> # Le nom du dashboard est le même que celui défini dans dbt_project.yml.
```

::alert{type=info}
Consultez `core.dashboards_store/dbt_project.yml` pour trouver le *tag* du modèle à exécuter.
::


#### À propos du sélecteur `+` et de l'option `--select`
::alert{type=info}
Vous aurez *probablement* besoin du sélecteur `+` pour exécuter les modèles avec l'option `--select`.
::

Si vous voulez exécuter à la fois un modèle et ses dépendances en amont, utilisez le sélecteur `+`. C'est généralement nécessaire parce que les modèles dépendent de *seeds* et de sources.

```bash
dbt build --select +tag:<nom_du_dashboard> # Le nom du dashboard est le même que celui défini dans dbt_project.yml.
```
ou

```bash
dbt build --select +<nom_du_modele> # Le nom du modèle est le nom du fichier SQL sans l'extension.
```
